## 유지한 계약

- raw6 순서·계산 의미, X8 입력, 기존 배포 Logistic 모델·스케일러·학습 계수 유지.
- OSM 방향성·회전 제한·부분 arc 계약, Q4 4문항 및 제한된 보조 추천 방식 유지.
- 예전 검색·노출·선택 snapshot을 수정하지 않음. 예전 노출은 `legacy_rendered_v1`, 실제 가시성 측정은 `visible_cards_v2`로 구분.
- 새 행동 보정은 `visible_cards_v2`의 실제 비교 가능한 선택만 사용. 한 후보만 확인한 선택은 저장하되 학습용 쌍을 생성하지 않음.
- GPS 안내, 시뮬레이션, 재검색, 즐겨찾기, 관리자 화면의 기존 흐름을 회귀검사함.

## 알고리즘·모델 검증

`npm run test:local`은 데이터 해시·SQLite 무결성, 실제 도로 경로 재계산, Q4 도로 사례, A*/Dijkstra 비교, Yen 상위 K/동점/확장 상태, no/only 제한 및 root-spur 경계, 모델 추론, 개인화, 학습 입력, 임시 PostgreSQL을 검사한다.

추가 검사는 다음을 확인한다.

- 부담 기여도의 지표별 합계가 원본 raw6와 일치하고, 모든 구간 위치가 경로 길이 안에 있으며, 연속 동작 간격이 동결 규칙의 100m 이내인지 확인.
- 실제 HTTP 검색 연결을 끊고 계산기가 짧은 시간 안에 다음 요청을 처리하는지 확인.
- DB 작업 임대 만료·이전 토큰·작업 도중 새 선택·재시도·중복 선택·설정 초기화·비활성 모델·중복 채택 검사.
- 실제 Chrome에서 자동 선택 금지, 실제 노출 집합, 선택 출처, 부담 지도 이동, 새로고침, 모바일 스크롤, GPS·음성·재검색 검사.

모델 검사는 합성 테스트셋과 저장 모델의 재현성 검사다. 실제 이용자 추천 성능을 입증한 결과가 아니다. 서비스에 사용하는 Logistic 모델의 런타임 확률은 기준 구현과 부동소수점 오차 수준으로 일치한다. 비교용 XGBoost는 후보 순서를 뒤집었을 때 대칭성이 보장되지 않으며, 서비스 추천 모델로 바꾸지 않았다.

## 성능 검사와 한계

`scripts/compare-routing-performance.py`는 변경 전 통합 탐색과 최종 통합 탐색을 같은 데이터·핵심 그래프에서 별도 프로세스로 실행한다. 근거리·중거리·강 건너기·장거리의 소요 시간, 응답 크기, 최대 작업 메모리를 기록한다. 시간 제한에 걸리지 않은 사례의 최종 경로 해시가 같아야 통과한다.

한 번의 비교 실행은 전체 사용 환경의 성능 보장이 아니다. 장거리에서는 기존 25초 탐색 예산으로 후보 생성이 잘릴 수 있다. K=10은 탐색 목표이며, 반환 후보가 전체 도로의 전역 최적해라는 의미는 아니다. 부담 최소 탐색의 초기 A*는 연속 동작까지 포함한 최종 raw6 목적함수의 전역 최적성을 보장하지 않는다.

부담 설명은 도로 속성·형상에 근거한 지표이며 실제 차로 변경 지시나 사고 위험 예측이 아니다. 도로 연결점까지의 점선은 차량 진입·보행 가능성을 보장하지 않는다. 정식 서비스의 보관·삭제 운영 정책과 실제 도로 현장 검증은 별도로 남아 있다.

## 운영 반영

- 기존 DB: `database/manage.py flow`로 추가 마이그레이션 적용. 기존 이력 유지.
- 신규 DB: bootstrap에 추가 대기열·RPC 포함. 기존 DB에 bootstrap을 실행하면 거부한다.
- Python worker 수정 후 `node scripts/build-runtime-manifest.mjs`로 실행 코드 해시를 갱신하고 worker를 재시작해야 한다.
- 정책 원본: `ml/personalization_policy.json`. Python과 Node가 같은 파일을 읽는다.
- 카카오 지도는 허용된 앱 주소가 필요하다. 별도 포트 5183에서 로드 실패, 기존 5173에서는 지도·장소 검색을 확인했다.

검사 원본 보고서는 `.test-tools/service-routing-report.json`, `algorithm-report.json`, `model-verification.json`, `personalization-report.json`, `service-db-report.json`, `service-api-report.json`, `ui-results/report.json`, `performance-comparison.json`에 저장된다. 이 파일들은 로컬 검증 산출물이며 Git 추적 대상이 아니다.

- 개인화: 17개 검사, 학습 데이터 계약 11개 검사 통과.
- 임시 DB: 57개 검사, 실제 PostGIS의 신규 구성 및 롤백: 9개 검사 통과.
- 실제 API: 75개 검사 통과. 검색 취소 후 미저장·같은 ID 재시도, 부담 설명 소유권, 선택 멱등성, 개인화 설정·관리자 권한 포함.

위 수치는 같은 PC에서 각 사례를 한 번 실행한 결과다. 장거리는 전후 모두 후보 생성 제한에 걸렸으며, 최종 후보가 같더라도 생성한 전체 후보 수는 달라질 수 있다. 최대 작업 메모리는 약 1,898MB → 1,911MB였다. 전체 환경에서 성능 저하가 없다고 단정하지 않는다. 부담 설명은 별도 요청으로 계산하므로 표의 검색 응답 크기에 포함되지 않는다.

취소는 대기·계산을 중단하고 떠난 화면에 늦은 결과를 적용하지 않는다. 이미 DB 저장 단계에 진입했거나 저장을 마친 검색을 취소를 이유로 역삭제하지는 않는다. 검색 저장과 사용자 선택 기록은 별개이며 최종 선택은 계속 명시적 사용자 동작을 요구한다.
