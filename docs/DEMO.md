# 안전하길 시연 안내

## 시작

프로젝트 루트에서 `npm start -- --api-port=3001`을 실행한다. 사용자 **http://localhost:5173**, 관리자 **http://localhost:5174**. 기존 실행이 포트를 사용하면 그 개발 터미널을 먼저 종료한다. 인터넷이 필요하며 기존 계정으로 로그인한다.

신규 이메일 계정은 이메일 확인이 필요하다. 카카오·구글·네이버는 제공자의 인증 화면 연결까지 확인했다. **본인 계정의 최종 소셜 동의/복귀와 인증 메일 수신은 발표 전에 직접 한 번 확인한다.** 자동 검증은 임시 확인 계정으로 로그인부터 진행했고 종료 시 삭제했다.

## 3~5분 시연 순서

1. 새 설문에서 운전 빈도를 선택하고 **복잡한 교차로 2순위 / 좁은 도로 1순위 / 어린이 시설 주변 3순위**로 설정한다. 나머지는 미선택.
2. Q4 네 문항에 A/B를 선택하고 한 번은 “판단하기 어려워요”를 선택한다. Q4는 행동 이력과 별도임을 설명한다.
3. 경로 검색 화면의 **예시 구간 A**를 누른다. 실제 도로 계산으로 1~3개 카드를 표시한다. 같은 경로의 유형은 한 카드에 합쳐진다.
4. 지도와 부담 지표를 비교하고 “모델 추천” 표시가 경로 유형과 별개임을 보여준다.
5. “이 경로 선택하기” → 새로고침 → 마이페이지의 최근 경로에서 선택 결과가 유지됨을 보여준다.
6. 운전 선호 설정에서 설문/적용 가중치, 행동 보정 상태, 끄기·초기화를 확인한다. 10건 미만에서 보정되지 않는 것이 정상이다.
7. 관리자 대시보드에서 실제 검색·선택 수와 모델/데이터 상태, 경로 기록을 보여준다.

예시 A는 고정 기준시각(2026-09-16 08:00 KST)의 재현 가능한 계산이다. 일반 장소 검색은 검색 시각을 사용한다. 지도에서 도로를 직접 선택할 수 있으며, 시설 중심점이 지원 도로에서 40m 이상 떨어지면 가까운 도로 위치를 선택한다.

추가 검증 OD는 `scripts/benchmark-routing.py`의 nearby/medium/cross_river/long에 있으며 좌표·실행 결과는 실행 후 `.test-tools/routing-benchmark.json`에 저장된다. 고정 좌표라도 최신 상용 내비의 통행 가능성을 보증하는 자료는 아니다.

로컬 계산시간 관찰치(ETA 예측 시간이 아님, 이 PC에서 다른 검증과 병행한 1회 측정):

검색은 한 번에 하나를 처리한다. 계산 중 중복 요청은 재시도 안내를 반환한다. 탐색 목표는 25초이며 이미 시작한 후보 검산/응답 저장 시간은 추가될 수 있다. 경로가 없거나 시간 안에 검증하지 못하면 명시적 오류를 반환한다.

## 발표에서 사용할 수치와 설명

**팀 합성 Test 900 pair / 450검색** 기준이다.

| 모델 | Pair accuracy | ROC-AUC | Log Loss | Top1 |
|---|---:|---:|---:|---:|
| Logistic | 88.22% | 0.95735 | 0.27047 | 80.00% |
| XGBoost | 86.56% | 0.94784 | 0.29347 | 78.44% |

Logistic은 사전에 우선한 Validation Log Loss(0.28226 vs XGBoost 0.29518)를 기준으로 선정했다. Test를 모델 선정에 쓰지 않았다. 공통 모델 하나에 사용자별 가중치가 반영된 X8을 넣는다. XGBoost에도 동일한 대칭 확률 처리를 적용했다.

- “안전점수”나 사고 감소율이 아니라 **운전 부담 비교/선호 추천**이다.
- 현재 모델의 실제 사용자 성능은 미검증이다. 행동 보정도 정책을 명시한 파일럿이다.
- Q4는 응답 저장 기능이며 현재 추천을 자동 변경하지 않는다.
- 도로/ETA는 동결 자료·과거 시간대 교통과 대체 속도다. 실시간 교통과 주행 안내를 제공하지 않는다.
- 서울 경계 안에서도 OSM 지원 도로·회전 제한·스냅 조건에 따라 탐색 실패나 큰 우회가 가능하다. 상용 내비와의 일치나 도로 전체의 전역 최적 경로를 보장하지 않는다.

```powershell
npm run test:local
npm run build
npm run test:api -- --api-url=http://localhost:3001/api
npm run test:ui
npm run test:ui:admin
.\.venv\Scripts\python.exe -X utf8 ml/src/train.py

```

API/화면 검사는 실행 중인 서비스와 Supabase service key가 필요하며 임시 계정을 만들고 정리한다. Chrome 기본 설치 경로를 사용하며 다르면 `CHROME_PATH`를 지정한다. 결과·스크린샷은 `.test-tools/`에 저장되고 Git에서 제외된다.
